Git Reference Guide

Cẩm Nang Các Lệnh Git

Tổng hợp đầy đủ các câu lệnh Git thông dụng và nâng cao dành cho lập trình viên. Tra cứu nhanh, sao chép bằng 1 cú click.

Quy trình làm việc (Git Architecture Workflow)
1. Working Directory
Thư mục chứa mã nguồn làm việc trực tiếp trên máy của bạn
git add . ➔
2. Staging Area (Index)
Nơi tập hợp các thay đổi sẵn sàng để đóng gói commit
git commit -m ➔
3. Local Repository
Kho lưu trữ lịch sử commit trên máy cá nhân (.git)
git push ➔
4. Remote Repository
Kho mã nguồn chung từ xa (GitHub, GitLab, Bitbucket)
⮜ git pull / fetch

1. Khởi tạo & Cấu hình (Setup & Config)

4 lệnh
Khởi tạo Repository Cơ bản

Khởi tạo một Git repository mới trong thư mục hiện tại.

git init
Clone Repository Cơ bản

Tải về một repository hoàn chỉnh từ remote server về máy.

git clone <repo-url>
Cấu hình Tác giả Setup

Cài đặt tên và email sẽ gán cho các commit của bạn.

git config --global user.name "Tên Bạn"
Cấu hình Email Setup

Cài đặt email cho commit trên toàn bộ hệ thống.

git config --global user.email "email@domain.com"

2. Lưu Thay Đổi (Staging & Commits)

4 lệnh
Đưa file vào Staging Cơ bản

Thêm toàn bộ file thay đổi vào staging để chuẩn bị commit.

git add .
Thêm File Cụ Thể Cơ bản

Thêm chính xác một tập tin được chỉ định vào staging.

git add <file-path>
Tạo Commit Mới Cơ bản

Ghi nhận phiên bản lưu mới kèm theo thông điệp mô tả thay đổi.

git commit -m "Thông điệp commit"
Sửa Commit Gần Nhất Mẹo hay

Gộp thêm file mới hoặc sửa đổi nội dung tin nhắn commit gần nhất.

git commit --amend

3. Quản Lý Nhánh (Branching & Merging)

5 lệnh
Liệt kê các nhánh Nhánh

Xem danh sách các nhánh local và biết được nhánh đang kích hoạt.

git branch -a
Tạo & Chuyển nhánh mới Khuyên dùng

Tạo mới một nhánh và lập tức chuyển sang làm việc trên nhánh đó.

git checkout -b <ten-nhanh>
Chuyển sang nhánh có sẵn Nhánh

Chuyển đổi vùng làm việc sang một nhánh đã tồn tại.

git switch <ten-nhanh>
Hợp nhất nhánh (Merge) Nhánh

Hợp nhất nội dung từ nhánh được chỉ định vào nhánh hiện tại.

git merge <ten-nhanh>
Xóa một nhánh Dọn dẹp

Xóa an toàn nhánh đã được hợp nhất.

git branch -d <ten-nhanh>

4. Remote & Đồng Bộ Hóa (Remote & Sync)

4 lệnh
Kết nối Remote Repository Remote

Liên kết kho cục bộ với một remote repository từ xa (thường đặt tên là origin).

git remote add origin <url>
Đẩy commit lên Remote Đồng bộ

Đẩy toàn bộ commit của nhánh lên server remote (GitHub, GitLab).

git push -u origin <nhanh>
Kéo mã nguồn mới nhất (Pull) Đồng bộ

Tải về và gộp ngay thay đổi mới nhất từ remote vào nhánh làm việc hiện tại.

git pull origin <nhanh>
Cập nhật thông tin Remote (Fetch) Đồng bộ

Tải dữ liệu mới nhất từ remote về nhưng chưa tự động merge vào code hiện tại.

git fetch --all

5. Trạng Thái & Lịch Sử (Status & Logs)

3 lệnh
Kiểm tra trạng thái Cơ bản

Hiển thị các file đã sửa, chưa track hoặc đã đưa vào staging area.

git status
Lịch sử commit dạng đồ thị Hữu ích

Hiển thị lịch sử commit cô đọng trên 1 dòng kèm nhánh trực quan.

git log --oneline --graph --decorate
Xem chi tiết thay đổi (Diff) Kiểm tra

So sánh nội dung các dòng vừa sửa đổi so với lần commit trước.

git diff

6. Hoàn Tác & Cất Giữ (Undo & Stash)

4 lệnh
Hủy thay đổi trong file Hoàn tác

Khôi phục file chưa staged về trạng thái của commit gần nhất.

git restore <file-path>
Cất giữ tạm thời (Stash) Nâng cao

Lưu tạm các thay đổi đang làm dở mà chưa muốn commit để chuyển nhánh.

git stash
Lấy lại mã nguồn đã Stash Nâng cao

Áp dụng lại các thay đổi đã cất giữ trước đó vào vùng làm việc.

git stash pop
Quay lui Commit (Reset) Cẩn trọng

Hủy bỏ commit gần nhất nhưng vẫn giữ lại các thay đổi trong code.

git reset --soft HEAD~1

Kinh Nghiệm & Mẹo Làm Việc Với Git

  • Commit thường xuyên: Chia nhỏ các tính năng thành nhiều commit rõ ràng để dễ review và revert khi cần.
  • Tạo file .gitignore: Luôn cấu hình .gitignore để tránh commit các thư mục rác như node_modules/, file tạm, mật khẩu hoặc .env.
  • Đặt commit message chuẩn: Áp dụng chuẩn Conventional Commits (ví dụ: feat: thêm tính năng, fix: sửa lỗi, docs: cập nhật tài liệu).
  • Luôn Pull trước khi Push: Chạy git pull trước khi push code để tránh conflict với đồng đội.
